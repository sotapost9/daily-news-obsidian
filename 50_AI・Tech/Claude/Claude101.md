- アウトプットが一般的すぎる場合
	- プロンプトの基本と同じ。求めるアウトプットの明記、ターゲットや役割や背景の詳細情報を渡すなど
	- フォーマットも欲しい情報で明記すべき。箇条書きやら太字やら
- リサーチ時にハルシネーションがある場合
	- 情報ソース渡す、信頼度を示させる、回答を現在の情報に限定させるなど
- プロンプトのコツ
	- **最初のプロンプトで正解を出そうとしなくていい。クロードの理解やアウトプットを見て、プロンプトを洗練させていく**
	- FBは具体的にする。
- ワークフローにClaudeを組み込むために
	- Claudeがどこのフローで最も価値を発揮するかを明確に特定する
	- より文脈や例を丁寧に教える必要があるタスクも特定する
- 具体的にClaudeのワークフローを設計するために
	- まず自分たちが行なっているアウトプットの例を5−10案持ってくる
	- プロトタイプとなるプロンプトを極力文脈を加味して作ってみる
	- 上記を比較し、Claudeは重要な情報を捉えているか、トーンやスタイルは適切か、どこを改良すべきかを考える
- 3つのモード
	- Chat
		- **Option2回で呼び出し**
		- 画面を見せて質問可能
		- スクショをそのまま共有できるので説明コスト低い
		- 「control」2回押しで音声入力
	- Cowork
		- **重いリサーチや分析や成果物作成が用途**
		- **マルチタスク可能：複数作業を並行できる**
		- 要件（作業や形式）を明記してあげること
		- **定期タスクもできる？**
		- **Crome連携してブラウザ操作もできる？**
		- **チーム連携もできる**
	- Code
		- ソフトウェア開発が用途
