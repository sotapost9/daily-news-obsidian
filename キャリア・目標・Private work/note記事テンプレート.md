# 深読みノート 記事設計テンプレート

_2026-07-21 Claude Codeとのセッションより_

## 0. 記事を書く前に必ず確認する3点

```
① 誰に向けて書くか（ペルソナ「ハルカ」を思い出す）
② どのバズワード・トレンドから入るか（時事性・検索流入）
③ Sota固有の視点は何か（N1観察・現場経験・哲学対話・DEI・建築→コンサル経験）
```

③がないと「ただの解説記事」になる。①②だけ揃えてから書かない。

## 1. タイトルのパターン

### パターンA：逆説型（最もXで拡散しやすい）
```
「[一般的に正しいとされていること]」が、実は[意外な結論]だった
```
例：
- 「AIが賢くなるほど、取りこぼされる人が増える」
- 「推しに課金するのは、消費じゃない」
- 「余白が大事と言い始めた頃から、余白がなくなった」

### パターンB：問い型（哲学対話ターゲットに刺さる）
```
[みんながなんとなく感じている違和感]を、問いにする
```
例：
- 「山口周を読んでいるのに、なぜ自分の問いが消えていくのか」
- 「便利なのに、なぜ生きやすくならないのか」

### パターンC：定義型（シェアしたくなる一文）
```
[よく使われる言葉]は、実は[再定義]だ
```
例：
- 「推しへの課金は、優しい世界の維持費だ」
- 「エンパシーは、穴の中に一緒に入ること」

### 共通ルール
- 25文字以内を目安
- タイトルを見た瞬間に「誰向けか」がわかること
- バズワード（AI・推し活・余白・ウェルネスなど）を1語入れると初速が出る
- タイトル案を出す前に「このタイトルを見てXで止まる人は誰か」を問う

## 2. テーマの選び方

### 選ぶ基準（3つ全部揃うと強い）
```
時事性：今、X・ニュース・本屋でよく見るキーワードか
独自性：Sotaの現場経験・観察から語れるか
普遍性：ハルカが「自分ごと」として読めるか
```

### テーマのタネの見つけ方
1. **Vaultの日記LINEメモから**：「気になった・手が止まった」エントリーが記事の種
2. **本・映画・ポッドキャストから**：バズワードと自分の体験が交差した瞬間
3. **N1インタビューや現場観察から**：「これ誰も言語化してないな」という観察
4. **Xで先行テスト**：140字の問いを投げて反応を見てからnote化

---

## 3. 記事の全体フォーマット

### 構造：1テーマ×縦掘り型
1記事＝1テーマ。横に広げず、縦に深く掘る。
Lobsterrのような複数テーマ構成はメルマガ固有の形式なので真似しない。

```
冒頭リード（3行）
─────────────
Opener ：バズワード・実体験から入る
Aha①  ：「でも、実は」の逆説・深読み
Aha②  ：別の角度からの補強
Aha③  ：現在・社会・AIへのつなぎ
Closer ：自分がなぜ書くか・問いで終わる
─────────────
末尾の問いかけ（1行）
```

### 論旨の設計（書く前に決める）
- **演繹型**：結論→根拠→事例。「〇〇だと思う、なぜなら...」
- **帰納型**：事例→事例→結論。「こんな現象がある、あんな現象もある、つまり...」

どちらかを選んでから書く。混在させない。

## 4. 各パーツの書き方

### 冒頭リード（3行・太字）
- 文脈ゼロの人が5秒で「何の記事か」わかる
- バズワード・問題意識・読む人を1文ずつ
- 例：「AIやサービスが便利になるほど、その恩恵から外れる人もいる。悪意ではなく、効率を追うシステムが人を見えなくする。そのメカニズムを、一冊の哲学書と一本の映画を手がかりに考えます。」

### 章タイトル
- その章の結論・主張を一言で示す
- 読者がスキャンしたときに論旨の骨格がわかること
- 例（良い）：「「誰のために」が抜けるとき」「悪意がない人が人を消す」
- 例（悪い）：「はじめに」「問いの整理」「まとめ」

### 各章の長さ
- 1章：200〜350字（1〜2分で読める）
- 章が長くなりそうなら分割する
- 全体：800〜1,200字（スマホで読んで3〜4分）

### 章1（Opener）：実体験・バズワードから入る
- 必ず一人称の体験・感情から始める（「〜を読んでいて手が止まった」「〜を見たとき、�妙に引っかかった」）
- AIに書けない体験が1つ入っていること
- バズワードを使うなら冒頭で出す

### 章2〜4（Core）：深読み・独自視点
- 1章ごとに独立した1つのAha
- 本・映画・研究を引用するときは「〜を考えるヒントとして」という前置きを入れる
- 難しい固有名詞（哲学者・専門用語）は「少し難しい話をすると」でクッションを入れる
- 批評はベタ褒めでも単純批判でもなく、賛否を両立させる

### 章5（Closer）：自分がなぜこれを書くか
- なぜ自分がこのテーマを扱うのか（哲学対話・このnote・現場経験）
- 告知・誘導はここに自然な形で入れる
- 結論は出し切らない。「〜かもしれない」「〜という問いが残る」で余白を残す

### 末尾の問いかけ（1行）
- 読者への問い1つ
- 読んだ後に誰かに話したくなる形にする
- 例：「あなたのまわりで、便利になったのになんかおかしいと感じる場面、ありますか。」

## 5. リズムと文体の設計

### 文の長さ
- 短文と長文を交互に使う。同じ長さが続くとリズムが死ぬ
- 短文は断定・体言止め・問いに使う
- 長文は説明・背景・複雑な因果関係に使う

例（良い）：
> 満員電車。毎朝あれだけ人が押し込まれて、身体が密着して、自分のペースで動けなくなる。よく考えたら、相当な暴力だ。でも誰も怒らない。

例（悪い）：
> 満員電車では毎朝人が押し込まれており、身体が密着した状態で自分のペースで動けなくなるため、これは暴力と言えるかもしれませんが、誰も怒りません。

### 段落の長さ
- 1段落＝2〜4文を基本とする
- スマホで読むことを前提に、詰めすぎない
- 重要な一文は独立した1行段落にしてもいい

### 接続詞の使い方
- 「でも」「しかし」→逆接・転換のメリハリに使う
- 「だから」「だからこそ」→強調したい因果に使う
- 「ただ」→批評・留保の前置きに使う
- 「ここが」→核心を指し示すときに使う
- 多用しすぎない。1章に2〜3個まで

### 体言止めのタイミング
- 章の締め・段落の締めに使うと余韻が出る
- 連続して使わない（3文以上続くと単調になる）
- 例：「その怖さ。」「それだけの話。」「誰も責任を感じない。」

### 敬語のトーン
- 基本：です・ます調
- 断定したいとき：「〜だ」「〜ではない」（体言止めと組み合わせる）
- 話しかけるとき：「〜ですよね」「〜ですが」「〜んですが」はNG（「〜ですね」に統一）
- 「じゃない」→「ではない」、「でも」→文脈によって「しかし」に変える

### ユーモア・個人色の入れ方
- 1記事に1箇所だけ、軽いユーモアや自分の癖を入れる
- データの直後・重い話の直後に置くと緩急になる
- 例：「（ただ、日本野鳥の会公式の長靴は愛用している）」
- 無理に入れない。自然に出てきたときだけ

### 数字・統計の使い方
- 出すなら冒頭か章の最初の段落に置く。後半に埋めない
- 数字は「驚き」か「スケール感」の提示にだけ使う
- 出典は括弧でさらっと書く。注釈に逃がさない
- 例：「W杯はFIFAに約89億ドルをもたらした（BCG、2026年）」

## 6. 引用のルール

### 本・記事を引用するとき
- 引用する理由を先に書く。いきなり引用しない
  - 良い：「このテーマを考えるヒントとして、〜を紹介したい」
  - 悪い：「〜という本がある。〜と書かれている」
- 難しい固有名詞（哲学者・研究者）には前置きを入れる
  - 「少し話が難しくなるが」「急に学術的になるが」
- 著者名・本のタイトル・出版年は出す。訳者・出版社は省く
- Amazonリンクは本文中に自然な形で埋め込む（章末ではなく言及箇所に）

### 映画・作品を引用するとき
- 「なぜこの作品をここで出すか」を1文で添える
- 主演俳優・監督などの固有名詞は入れない（作品の内容だけ）
- あらすじは最小限。「〜の話」で済ませる

### 引用文を直接載せるとき
- 1記事に1〜2箇所まで
- ブロック引用（`>`）で視覚的に区別する
- 引用の前後に自分の解釈を必ず入れる。引用で終わらない

## 7. 締め方のパターン

### パターンA：問いで終わる（推奨）
読者に委ねる。So whatを出し切らない。読んだ後に誰かに話したくなる形。
> 「あなたのまわりで、便利になったのになんかおかしいと感じる場面、ありますか。」

### パターンB：自分の宣言で終わる
このnoteや哲学対話への誘導がある章に使う。
> 「だからこそ、問いを持ち寄る場をつくりたいと思っています。」

### パターンC：逆説で締める
記事の核心をもう一度別の角度から言い直す。
> 「便利になるほど、見えなくなる人がいる。」

### 共通ルール
- 結論を2回言わない（まとめ→締めで同じことを繰り返さない）
- 「いかがでしたか」「以上です」は絶対に使わない
- 末尾の問いかけは体言止めか短文で締める

## 8. Xシェアを意識した「抜き書き一文」の設計

note記事の中に、そのままXに貼れる一文を1つ設計しておく。

条件：
- 140字以内
- 記事を読んでいなくてもわかる
- 逆説・再定義・驚きのどれかがある
- 引用元として記事リンクが貼れる形

設計タイミング：記事を書き終えた後、Xシェア用の一文を1つ選ぶ（または書き直す）

例：
> 「推しへの課金は消費じゃない。やったことが返ってこない日常を生きる人が、唯一息継ぎできる場所を守るためのお金だ。」

## 10. 執筆後のレビューチェックリスト

```
□ タイトルを見て、誰が止まるか説明できるか
□ 冒頭3行で記事の趣旨が伝わるか
□ 自分の実体験・感情が1箇所以上入っているか（AI判別）
□ バズワード・トレンドが入口になっているか（時事性）
□ Sota固有の視点（現場・観察・哲学）が軸になっているか（差別化）
□ 章タイトルだけ読んで論旨の骨格がわかるか
□ 難しい固有名詞に前置きがあるか
□ 結論を出し切らず、問いで終わっているか
□ 「誰かに話したくなる一文」が1つあるか
```

## 6. 参考：Lobsterrとの差別化軸

| | Lobsterr | 深読みノート（Sota） |
|---|---|---|
| 情報源 | 英語圏一次ソース（外から） | 現場観察・N1体験（内から） |
| スタンス | キュレーター・編集者 | 当事者・観察者 |
| 強み | 情報の網羅性・翻訳速度 | 現場体験・哲学対話の実践知 |
| 読後感 | 「知らなかった情報を得た」 | 「自分ごとの問いが残った」 |

Lobsterrは「世界で起きていること」を届ける。深読みノートは「自分が経験したこと・感じたこと」から問いを届ける。この差が価値になる。
