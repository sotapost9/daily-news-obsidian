# N1インタビュー分析 → WOWインサイト導出フロー

タグ：#方法論 #インタビュー分析 #UXリサーチ #郵政

---

## 0. 概念定義

### Fact（ファクト）
インタビュー中に記録された**生の発言・行動・出来事**。解釈を含まない一次データ。

> 「ゆうちょの窓口で書類を3回出し直させられた」  
> 「『面倒くさいからそのまま』と言った」

KA法の「発話欄」に相当。**観察者が見たこと・聞いたことのみ。推論を含まない。**

---

### Finding（ファインディング）
複数のFactから抽出した**パターン・傾向・テーマ**。「実際に何が起きたか」を整理した共通認識。

> 「複数のインタビュイーが、金融相談の相手を比較・検索ではなく紹介や来訪から決めている」

KA法の「心の声」→ 小グループ命名に相当。**まだ「なぜ」は説明していない。**

⚠️ Finding止まりになるのは「なぜを問えていないから」。「心の声の翻訳」で止まって「価値の命名」まで踏み込めていないケース。

---

### Insight（インサイト）
Findingの背後にある**意味・構造・動因への理解**。なぜそれが起きたのか、何を期待・恐怖・欲望していたのかまで含めた解釈。

> 「相続の相談相手は資格や機能では決まらない。『すでに人間関係がある人』だけが相談相手になる——なぜなら相続・終活は財産・家族・死という三つの最も繊細な情報が絡み、見知らぬ人には話せないという根本的な恐怖があるから」

KA法の「価値命名・大グループ」に相当。**「行動の説明」ではなく「動因（動機・恐怖・欲望）の説明」になっている。**

---

### WOWインサイトの条件

「驚くけど言われてみれば確かに納得」——これが力強いInsightの構造。

**認知科学的根拠（Ahaモーメント）**

InsightのトリガーはO**認知的不協和**。既存のメンタルモデルに合わない情報に向かうことで生まれる。Ahaモーメントは4つの特徴を持つ：突然性・流暢性・ポジティブな感情・確信感。驚きがあるからこそ流暢に処理されて確信が生まれる（Topolinski & Reber, 2010）。

**WOWインサイト4条件**

| 条件 | 問い | 例 |
|------|------|---|
| ① 矛盾・テンション構造 | 「〜なはずが実は〜」が成立するか | 「愛されているが使われていない」 |
| ② ステークホルダーの前提を壊している | 「えっ」と言うか | 「窓口案内をしても相談は来ない」 |
| ③ 普遍的な人間心理に接地している | 誰もが「確かに」と言えるか | 「知らない人には大事な話ができない」 |
| ④ 離れたドメインのデータを接続している | 複数の調査軸をまたいでいるか | 「葬儀体験が金融選択を決める」 |

**テンプレート構造**
```
「[ユーザー属性]は[Xしたいと思われている]。
しかし実際には[逆のY]だった。
なぜなら彼らは本当は[根本的な動因Z]を大切にしているから。」
```

**WOW自己チェックリスト**

| 問い | OKの状態 |
|-----|---------|
| ステークホルダーは知っていたか？ | 「えっ」と言う |
| ユーザー自身は気づいていたか？ | 言語化されていなかった |
| 「なぜ」まで答えているか？ | 動因の説明になっている |
| 矛盾・逆説が含まれているか？ | 「〜なはずが実は〜」が成立する |
| 普遍的な人間心理に接地しているか？ | 誰もが「確かに」と言える |

## 1. フロー全体図

```
インタビュー実施
        ↓
[Step 1] N1レポート作成（AI）
        ↓ ← 人間レビュー・補足（必須）
[Step 2] Fact抽出（AI + 人間補完）
        ↓
[Step 3] Finding導出（AI叩き台 + 人間判断）
        ↓
[Step 4] Insight生成・WOW判定（AI叩き台 + 人間最終承認）
        ↓
[Step 5] Obsidianグラフビューで構造確認
        ↓
[Step 6] 追加インタビューで担保を厚くする
```

Obsidianの `[[wikilink]]` が全レイヤーを貫く接着剤として機能し、グラフビューで分析構造が自動的に可視化される。

---

## 2. Step 1：N1レポート作成

**目的**：1人の体験・文脈・感情を構造化し、以降の分析の土台を作る。

### AIのタスク

| セクション | 内容 |
|-----------|------|
| 基本情報 | 年齢・性別・居住地・職業・保有口座・家族構成 |
| スクリーナー | 参加条件の充足確認 |
| 分析軸1：相続ジャーニー | 時系列の体験・感情の変化 |
| 分析軸2：家族コミュニケーション | 誰と・何を・どう話したか |
| 分析軸3：ゆうちょ・金融接点 | 接触履歴・評価・行動変容 |
| 感情体験マップ | ジャーニー上の感情変化を+/−で記述 |
| 特記事項 | 他インタビュイーと明らかに異なる点 |
| ラップアップ要約 | この人を一言で表すと |
| 発言カード一覧 | 印象的な発言を引用形式でリスト |

### 人間のタスク（必須）

AIは「明示的に語られたこと」は拾えるが、**文脈・含意・沈黙・言葉の選び方**を落とす。インタビューを実施した人間だけが持つ情報がここにある。

- 読み直して「抜けている重要観察」を補足する
- 「言っていることとやっていることが違う瞬間」を追記する（ここにInsightの種がある）
- 補足した観察をAIに渡して次のステップで反映させる

---

## 3. Step 2：Fact抽出

**目的**：N1レポートから「注目すべき発言・行動」を個別ファイルとして切り出す。後でFinding/Insightに接続する素材になる。

### Factファイルの構成

```markdown
# 発言カード：[印象的な発言の一部を見出しに]

## 発言者
## 発言・行動（引用形式）
## 文脈（いつ・どんな流れで出た言葉か）
## 前後の発言
## この発言・行動が重要な理由（含意・他との比較・初期解釈）
## 参照候補（wikilink：接続先のFinding/Insightを先回りで記載）
```

### ファイル命名規則

```
発言_軸[1/2/3]_[ニックネーム]_[発言内容を動詞句で]
```

例：`発言_軸1_かげとら_ゆうちょたらい回し体験で解約を検討している`

### AIのタスク

1インタビューにつき15〜20本のFactを抽出・作成する。

### 人間のタスク

「このFactが落ちている」という補完。特に以下を確認する：
- 言っていることとやっていることが**逆**の瞬間
- 感情が動いた瞬間（声のトーン・沈黙・言い直し）
- 他のインタビュイーと明らかに異なる点

---

## 4. Step 3：Finding導出

**目的**：複数インタビュイーのFactを横断して「繰り返し観察されるパターン」を見つけ、命名する。

### ⚠️ AIに任せ切ってはいけないレイヤー

同じFactから複数の解釈がありえる。どの解釈が「より真実に近いか」は人間が判断する。AIは「可能な解釈の一つ」を「正しい解釈」として断言するリスクがある。

### Findingファイルの構成

```markdown
# Finding [番号]：[パターンのタイトル]

## フィンディングの要約（1〜2行）
## 担保発言・行動（インタビュイーごとの引用＋wikilink）
## 人物比較表（インタビュイー × 行動/属性のマトリクス）
## このFindingが示す構造（パターンのメカニズム）
## インサイントへの接続候補（wikilink）
```

### ファイル命名規則

```
Finding_軸[1/2/3]_[連番]_[パターンを動詞句で]
```

例：`Finding_軸1_11_揉めたくないが全ての行動の源泉`

### 人間のタスク（重要）

- 解釈の方向性を判断する
- Findingのタイトルが適切かを確認する（タイトルは以降の分析の方向性を規定する）
- 「似ているようで別のパターン」を分けるか統合するかの判断
- Finding止まりになっていないか確認する——「なぜ」まで問いを要求する

---

## 5. Step 4：Insight生成・WOW判定

**目的**：Findingを昇華させ、クライアントが知らなかった動因の説明としてのInsightを言語化する。

**Insight = Finding + メカニズムの解釈 + 事業的含意**

### Insightファイルの構成

```markdown
# WOWインサイントカード #[番号]

## タイトル（矛盾・逆説が見えるキャッチな一言）
## インサイント本文（80〜120字・常体）
   ── 「[属性]は[Xと思われている]が実は[Y]だった。なぜなら[動因Z]があるから」
## 背景にある本音（ユーザーが守ろうとしているもの）
## 根拠引用×3（異なるインタビュイーから・wikilink付き）
## 反証チェック（7観点）
## クライアントへの意味（具体施策3点以上）
## HMW（どうすれば〜できるか）
## WOW判定（4軸×★3段階）
## 仮説テーマとの紐付け
```

### 反証チェック7観点（全てクリアして初めてInsightとして成立）

1. ただの要約になっていないか？
2. 根拠引用は解釈を支えているか？
3. 反対の発言を無視していないか？
4. 少数意見で言い切りすぎていないか？
5. クライアントに都合よく解釈していないか？
6. 制度上・倫理上のリスクがないか？
7. より鋭い言い換えはあるか？

### WOW判定4軸

| 軸 | ★★★ | ★★ | ★ |
|---|---|---|---|
| 意外性 | 前提・常識を破壊する | 知っているが言語化されていない | 当たり前 |
| 根拠性 | 3名以上・独立した文脈 | 2名・関連ある文脈 | 1名のみ |
| 解釈の深さ | 動因（動機・恐怖・欲望）まで | 傾向の言語化 | 事実の記述 |
| 事業接続 | 明日から動ける施策 | 方向性は出る | 示唆が曖昧 |

### 人間のタスク（最終判断）

- WOW感を人間の感覚で判断する（採点より感覚が先）
- 反証チェックの甘い箇所を指摘する
- Insight間の重複・矛盾を整理する
- 「FindingレベルかInsightレベルか」を判断する
- ステークホルダーに見せて「えっ」が出るか試す

## 6. Step 5：Obsidianグラフビューで構造確認

### なぜグラフビューが有効か

Obsidianの `[[wikilink]]` を全ファイルに仕込むことで、グラフビューには以下の構造が自動的に浮かび上がる：

```
Fact（多数・小ノード） → Finding（少数・中ノード） → Insight（最少・大ノード）
```

これは**親和図法（KJ法）の動的・永続バージョン**として機能する。

### KJ法との対応

| KJ法の操作 | このフロー | Obsidianでの見え方 |
|-----------|----------|-----------------|
| 個別の付箋を書く | Fact作成 | 小さなノードが増える |
| 付箋をグルーピングする | Finding作成・wikilink付与 | FactノードがFindingハブに引き寄せられる |
| グループに命名する | Findingのタイトル | ハブノードのラベル |
| グループ間の関係を引く | Insight作成・複数Findingを参照 | 複数ハブが1つの大ノードに束ねられる |
| 全体構造を俯瞰する | グラフビューを開く | リサーチの地図が現れる |

KJ法との最大の違いは**動的に更新できる**こと。インタビューを重ねるたびにFactが追加され、Findingが更新され、Insightの根拠が厚くなっていく様子がグラフに反映される。

### グラフビューで分かること

**① 分析の「穴」を発見する**
- FactノードがどのFinding/Insightにも接続されていない → まだ昇華されていない観察
- FindingノードがどのInsightにも接続されていない → Findingで止まっている・「なぜ」まで問えていない

**② 証拠の強度を視覚的に確認する**
- あるInsightに接続されているFactノードが多い → 根拠が厚い（★★★の根拠性）
- Factが1〜2本しかないInsight → 担保が薄い・追加インタビューが必要

**③ クリティカルなFact（最重要観察）を特定する**
- 複数のFinding・Insightから参照されているFactノード → 複数の仮説を貫く一次データ
- エッジが集中するノード＝最も深掘りすべき観察

**④ インタビュイーのカバレッジを確認する**
- 特定のInsightに1名のFactしかない → 追加インタビューで担保すべき領域
- 全体の分布からリサーチの「飽和点」が見える

**⑤ フォルダフィルタで層別表示**
- Factフォルダのみ → 観察の全体量と分布
- Insightのみ → 結論の全体地図
- Fact + Insight → 根拠←→示唆の直接的な関係

## 7. 人間/AI 役割分担まとめ

| レイヤー | AIの役割 | 人間の役割 | 任せ切りのリスク |
|---------|---------|---------|--------------|
| N1レポート | 構造化・記述 | 読み直し・補足 | 文脈・含意・沈黙が落ちる |
| Fact | 抽出・初期解釈付与 | 重要観察の補完 | 「言っていることとやっていることの逆」を見落とす |
| Finding | グルーピング叩き台 | **解釈の方向性判断** | 複数ありうる解釈の一つを断言する |
| Insight | 仮説生成・反証 | **最終採用判断・WOW感の確認** | 採点スコアとWOW感は別物 |
| グラフビュー | wikilink自動生成 | 構造の確認・穴の発見 | — |

## 8. 関連手法との位置づけ

| ステップ | KA法 | Grounded Theory | Braun & Clarke（2006） |
|---------|------|-----------------|----------------------|
| Fact | 発話欄 | 生コード（Open Coding） | Level 1: 記述的水準 |
| Finding | 心の声 → 小グループ | カテゴリ | Level 2: カテゴリ的水準 |
| Insight | 価値・大グループ命名 | 中核カテゴリ → 理論 | Level 3-4: 解釈・理論的水準 |
